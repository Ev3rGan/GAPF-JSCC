# GAPF-JSCC 最终论文成稿要求与验收标准

> 公开说明：本文给出当前 GAPF-JSCC 工作稿的成稿门槛。它用于质量审计，不代表论文已经通过所有检查，也不替代投稿系统的正式要求。

本文档定义“完成”是什么意思。它用于阻止把局部改正、可编译 PDF 或主观顺畅感误判为论文已经达标。

## 1. 稿件成熟度

### M. 内容母稿

- 在逐模块访谈完成后建立，不受 Letter 页数和图位限制。
- 必须完整闭合问题定义、相关工作缺口、完整前向过程、必要公式、公式直释、实验责任和证据边界。
- 它是压缩来源和审计对象，不是投稿稿；不能因为内容母稿较长而提前删除因果桥梁或符号说明。
- 内容母稿未通过模块与公式验收前，不进入正式 Letter 压缩。

### A. 结构工作稿

- 允许正式结果、作者信息和图件保留 TBD。
- 论证主线、章节职责、方法数据流和实验责任必须已经稳定。
- 当前 V4 仍处于该阶段。Figure 1、Figure 2、两张 ADE20K 主结果图与 Kodak 样本 24 可视化已经进入正文，主结果证据与模块级写作合同已经形成；式（3）/式（5）的 GLINT 接口、简化后的辅助终端公式、Figure 2 caption 局部记号及 optimizer/learning-rate 已由实现、配置或已确认写作合同闭合。当前 Letter 已明确不设消融小节，消融不再是内容完整性缺口；作者与资助信息仍未闭合，Abstract、Introduction、Experimental Results 与 Conclusion 的现有具体表述也仍待按最新合同统一审核，因此 V4 尚不属于内容完整稿。

### B. 内容完整稿

- 所有科学内容、结果、图表、作者信息、声明和引用均已补全并经证据核对。
- 不存在结果 TBD、占位图、占位表或未经验证的结论。
- 全文通过本文件的内容验收，但尚可进行投稿格式压缩和语言精修。

### C. 最终投稿稿

- 内容完整稿通过作者逐项批准。
- 满足投稿时有效的 IEEE Communications Letters 模板、页数、摘要、参考文献和声明要求。
- 当前阶段的 Letter 正式工作稿按作者指令控制在 6 页以内；只有作者明确启动最终投稿压缩后，才强制收敛到届时适用的正式上限。

## 2. 一票否决项

出现任一项，稿件不得称为完成：

- 保留公式中存在未定义、延迟定义或职责不稳定的论文特有符号；
- 公式说明不能用原符号复述输入—运算—输出关系；
- 公式只有逐项计算释义，却不能说明整组关系表达的结构、约束及其与局部问题的对应关系；
- 关键方法只能依靠图、代码或 companion 才能理解；
- 方法声称的机制在公式或前向关系中不可见；
- 已确认的问题含义、顺序或机制映射在分析、母稿、正式稿、图件与 GitHub companion 之间发生未经作者确认的漂移；
- 结果或结论缺少正式证据、使用未完成实验或隐去不利条件；
- 把在所测条件下只有极小增量或未触发的辅助机制，写成已被消融证明的主要性能来源、质量增益或稳定性增益；
- 方法、实验协议、图表、摘要和结论之间存在对象、预算、数据、指标或数值不一致；
- 最终稿仍含 TBD、占位图、占位表、未核对引用或缺失作者声明；
- 仅凭编译、页数或视觉排版通过宣布科学内容完成。

## 3. 全文级验收

- [ ] 全文只有一条顶层论证主线，摘要、引言、问题定义、方法、实验和结论对同一问题作答。
- [ ] 完整系统是贡献和结果单位，GLINT 与 GAPF 是互补职责而非两篇拼接的方法。
- [ ] 术语一词一义，缩写首次展开，对象命名符合通信、机器学习和生成模型领域惯例。
- [ ] 读者无需了解 V1、DNLT、SACRA、代码目录或项目历史。
- [ ] 不看图完成一次从 $\mathbf x$ 到 $\widehat{\mathbf x}$ 的 teach-back，并能解释每个核心公式为何存在。
- [ ] 数学保证、设计意图、经验结果和推测严格分开。
- [ ] 所有事实性与数值性主张具有可复核来源；未知内容保持 TBD，而不是由流畅文字填补。
- [ ] 每个模块均能对照其受控语义合同逐项验收；不同载体可以压缩措辞，但问题含义、因果顺序、机制职责和对象命名保持一致。

## 4. 分模块成稿标准

### Abstract

- [ ] 长度为 75--100 词。
- [ ] 读者能在一段内识别中心问题、完整方法、两阶段互补职责、评测对象和系统级主要结果。
- [ ] 最后只用一句系统级定性结果概括感知质量优势及像素保真 trade-off；不包含精确 CBR/SNR、指标数值、分阶段结果或实验网格。
- [ ] 摘要中的每一项结果都能在正文和图表中找到完全一致的证据。

### Introduction and related work

- [ ] 从 DeepJSCC 到重建型 JSCC、生成型 JSCC、研究缺口和本文方法的过渡自然且必要。
- [ ] 每篇相关工作的篇幅由其与本文问题的关系决定，不追求统一信息卡或完整综述。
- [ ] 明确说明本文从哪些通信或跨领域思想获得启发，以及直接迁移为何不足。
- [ ] 贡献固定为四条：完整系统与问题、GLINT 的派生接口职责、GAPF 核心创新、完整系统实验验证；每条均由后续方法或实验兑现，不把协议、写作组织或未验证主张包装为贡献。

### System model and problem formulation

- [ ] 信道、预算、发送内容、接收端已知信息、冻结资源、训练对象和输出全部明确。
- [ ] Stage 1 与 Stage 2 的输入、输出、职责和连接关系在方法细节前可见。
- [ ] Figure 1 与正文共同建立同一条从源图像到最终重建的主路径；直接 VAE 解码只作为 GLINT 训练/诊断对象，不被画成第二个同等地位的系统终点。
- [ ] 正文只陈述科学边界，不出现“为了说明清楚”“区别于某方案”等作者编辑理由或防御性元话语。
- [ ] 问题定义能直接导出后续设计要求，而不是事后为已有模块寻找理由。

### Stage 1: GLINT

- [ ] 按固定顺序说明三个局部问题：VAE latent 通道数值尺度不均；latent 局部空间可预测性尚未组织成适合带宽受限链路的表示；latent 数值误差与冻结 VAE 解码后视觉影响不一致。
- [ ] calibration、lifting、固定预算压缩、信道、synthesis、逆变换和训练目标形成连续数据流。
- [ ] 最小 lifting 公式同时显示 $2\times2$ polyphase 分量、三个 prediction residual、coarse-field update 与逆关系；正文说明该结构为何组织了局部空间可预测性，而不只逐项翻译公式。
- [ ] GLINT 专属式（4）--（6）全部通过公式与符号审计；最终采用的 lifting-domain 表示、发送符号、接收符号、接收 latent anchor 和两类损失均有明确职责，且符号符合领域惯例。
- [ ] 不比较 DNLT，不引入 V1 方法或 nested GLINT 负结果。

### Stage 2: GAPF

- [ ] 读者先获得一次完整推理流程，再阅读局部机制。
- [ ] GAPF 开头给出最小 frozen-flow baseline；读者能用公式解释冻结 prior velocity 如何形成 clean-latent estimate、冻结 scheduler 如何更新下一状态，并能逐项指出 initialization、proposal conditioning 和 anchor-relative acceptance 相对 baseline 改了什么。
- [ ] 三步核心问题链按已确认顺序出现：接收 latent 进入生成状态、轨迹形成期间持续接收空间证据、限制 proposal 相对 anchor 的位移；信道状态协调其强度。终端细化与信赖域投影明确定位为辅助端点机制，没有与三项 trajectory 机制并列或被写成主要性能来源。
- [ ] `posterior` 被操作性定义为冻结 prior 在 $\widehat{\mathbf z}$ 与 $\gamma$ 条件下的学习式近似恢复过程；正文没有用缺乏实际 likelihood 的概念因子分解冒充模型事实。
- [ ] anchor initialization、TSET-conditioned proposal、anchor-relative acceptance 和 channel-state coordination 的核心职责清楚；辅助 terminal path 与核心 trajectory 的层级边界清楚。
- [ ] TSET 公式能与 baseline velocity/proposal 逐项对照；读者能指出它改变 proposal formation 的位置，而不会误解为替代冻结 prior。
- [ ] Anchor-relative acceptance 的公式显式以 $\widehat{\mathbf z}$ 为位移参照，并保留 unchanged scheduler update、线段关系和范数收缩这一直接性质。
- [ ] 辅助 terminal path 只保留 $\mathbf z^{\rm flow}$、$\boldsymbol\Delta$、复合校正算子 $\mathcal R_{\phi_R}$、$\alpha(\gamma)$、trust projection、$\mathbf z^\star$ 和直接 RMS 幅度上界；内部 gate、尺度匹配与投影细节已被忠实封装，而非伪装为核心公式。
- [ ] $\beta(\gamma)$ 与 $\alpha(\gamma)$ 的范围、单调方向和各自作用明确；$\beta$ 协调核心的 proposal acceptance，$\alpha$ 调节辅助端点校正，二者都没有被包装为独立贡献。
- [ ] GAPF 两职责训练目标位于完整推理链之后，并同时闭合可训练/冻结边界；TBPTT-1 与更新数留在训练或实验协议。
- [ ] GAPF 式（7）--（13）全部通过公式与符号审计；每个中间量有 producer 和 consumer。
- [ ] 先验补充细节与信道锚点约束之间的关系由公式可见，而非只由散文或图声称。

### Experiments

- [ ] 当前 Letter 的实验大章节只有 `Experimental Setup` 和 `Experimental Results` 两个二级模块；不存在 `Ablation Study`、消融表或消融 TBD。
- [ ] Setup 严格按“数据集与处理 → 指标职责 → 比较方法与公平性 → 训练/推理实现”组织；给出已经权威配置/manifest 核验的数值（GLINT：AdamW，峰值 $5\times10^{-4}$；GAPF：AdamW，TSET/terminal correction 为 $10^{-4}$、SNR controllers 为 $10^{-3}$），并明确先训练 GLINT、再在冻结 GLINT/VAE/flow prior/scheduler 条件下训练 GAPF 的边界。
- [ ] 协议定义数据、CBR/SNR、训练/评测边界、比较对象、随机性控制、指标和必要的不确定性处理。
- [ ] 每个结果段包含“条件/问题 → 直接观察 → trade-off/例外 → 有界解释”四层；定性为主、定量为辅，未逐曲线和逐点复述。
- [ ] 先分析 CBR $1/96$，再说明在更受限的 CBR $1/192$ 下优势仍然保持；两图纵轴各自适配数据，不用视觉斜率替代数值比较。
- [ ] 主结果唯一结论是跨两种 CBR 与所测 SNR 的稳定 LPIPS 优势及条件相关的 FID/保真表现，从而形成有利的 fidelity--perception trade-off，而非所有指标普适领先。若使用数字，仅保留必要的 LPIPS 辅助证据。
- [ ] 完整系统评测回答顶层问题；GLINT 只作 Stage-I direct-decoding 内部参考。主结果未把整体性能变化归因于单个 GAPF 组件。
- [ ] 所有比较公平且可复核，负结果和不提升条件未被选择性省略。
- [ ] Kodak 样本 24 只承担可视化：各列使用相同裁剪与倍率，重建下方只显示逐图 PSNR/LPIPS；不存在 Kodak 汇总均值或数据集级定量结论。
- [ ] Kodak 正文以可见边缘、纹理和局部结构完成“重建型模糊—生成型不合理细节—GAPF 更清楚且更协调”的三层比较，并支撑与主结果一致的 fidelity--perception 结论；未声称精确恢复不可观测细节。
- [ ] 两项受控移除的负结果保留在 companion 决策/证据记录中；正文、贡献和结论未将终端细化或信赖域投影写成已验证的主要性能来源，也未用该证据归因 TSET 或 trajectory acceptance。

### Conclusion

- [ ] 只完成三项职责：回答最初的接口问题；概括 GLINT/GAPF 的互补角色；总结完整系统的感知优势与像素保真 trade-off。
- [ ] 不新增方法、结果或泛化主张，不列精确实验网格，不重复机制清单。
- [ ] 不额外添加第四条局限性、未来工作或重复作用域限定的句子。

## 5. 公式和符号验收

- [ ] `公式与符号审计表.md` 中所有保留公式状态均为 `PASS`，且不存在“基本通过”。
- [ ] 每个公式后的说明包含式中实际记号，而不是仅使用自然语言别名。
- [ ] 每个核心公式组在计算直释之外，还说明其结构/理论含义、对应的局部问题和可由构造直接得到的性质。
- [ ] 首次出现的变量、算子、参数、上下标和上标均有稳定含义。
- [ ] 每个核心输出都在后续计算中出现，或正文明确说明其仅用于诊断/训练。
- [ ] 抽象算子的内部虽可省略，但其输入、输出、职责和训练状态不可省略。
- [ ] 已建立全局符号词典；发送量、接收量、估计量、流状态和最终输出无冲突、无一物多名，并符合通信与生成模型的常用记号直觉。
- [ ] 图注中的局部数学元记号也在首次出现时定义并登记审计表；其作用域清楚，不与正文方法对象混用。
- [ ] 系统式（1）--（3）、GLINT 专属式（4）--（6）和 GAPF 式（7）--（13）的编号范围与当前 TeX 一致。

## 6. 证据、实验和引用验收

- [ ] 所有数值与经冻结的正式 artifact、配置、样本数、CBR、SNR 和指标口径一致。
- [ ] pilot、smoke、进度探针和历史结果没有被写成论文结果。
- [ ] 已完成但未进入 Letter 的负结果在 companion 中保留完整条件、数值和结论边界，未被静默丢弃或改写为正向证据。
- [ ] 图、表、正文、摘要和结论中的重复数值完全一致。
- [ ] 引用元数据、方法归属和相关工作描述均已逐条核验。
- [ ] AI acknowledgement 使用作者批准的职责边界表述；匿名稿是否隐藏按实际投稿模式处理。作者、单位、资助、利益冲突和数据/代码可用性声明分别完成确认。

## 7. 语言与版面验收

- [ ] 完整进行一次术语审计、一次逐段逻辑审计和一次目标读者盲读。
- [ ] 不存在自创且未定义的术语、口语化表达、防御性说明或作者内部审计语言。
- [ ] 当前 Letter 工作稿为 US Letter 且不超过 6 页；最终投稿稿按作者启动压缩时确认的规则执行。
- [ ] 无 overfull、未解析引用、缺失字符或未嵌入字体；所有页面按最终尺寸渲染检查。
- [ ] 图表在最终尺寸可读，且只承担正文已说明内容的可视化职责。

本节的编译、字体和逐页视觉项目只在作者明确要求查看实际论文或进入提交检查点时执行；它们不是每次局部文字编辑后的默认动作。

## 8. 验收责任与输出格式

每次验收报告必须分别给出：

1. 已通过项目及其证据位置；
2. 未通过项目及其影响范围；
3. 仍属 TBD 或等待作者决定的项目；
4. 本轮是否仅完成局部修改、模块完成、内容完整或最终投稿验收。

禁止使用“整体已经很好”“没有明显问题”等无法复核的结论。作者对科学决策和最终提交保留最终批准权。
